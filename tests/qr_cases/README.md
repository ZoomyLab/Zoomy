# QR cases

[![QR cases](https://github.com/ZoomyLab/Zoomy/actions/workflows/qr-cases.yml/badge.svg)](https://github.com/ZoomyLab/Zoomy/actions/workflows/qr-cases.yml)

- **What:** every URL in the thesis QR manifest (`thesis/scripts/animations.yml`, snapshot `animations.yml` here). Each GUI session a code opens is composed as the GUI composes it (model, steps, mesh, settings, run, visualization) and executed through `library/zoomy_gui/engine.py`.
- **Solvers:** the sessions' solver cards run the symbolic solvers (`SymbolicHyperbolicSolverNumpy`, `SymbolicHyperbolicSolverJax`, `SymbolicHyperbolicSolverAmrex`; ported by `library/zoomy_gui/projects/tools/port_symsolver_sessions.py`); the coupling session replays a recorded preCICE run and solves nothing.
- **Wheels:** `docs/scripts/build_gui_wheels.py DIR` builds the `zoomy_core` / `zoomy_plotting` wheels the deployed GUI installs (`gui/gui/wheels/index.json`); CI installs the same build in CPython and Pyodide (`QR_WHEELS=DIR`). Without `QR_WHEELS` the tests build them for Pyodide and CPython reads the checkout.
- **CPython** (`-m qr`): jax blocked for browser-local sessions; the JAX session (`-m qr_jax`, Malpasset, `time_end` 2000 s cut to 2 s) adds `zoomy_jax` from the checkout. Pass = all cells succeed, every float in every HDF5 store finite, and a session that solves publishes its store (the run card's `open_hdf5(run_h5_path())`, the store the GUI shows and keeps) with at least 2 snapshots, the last at the session's `time_end` (`session_runner.final_store_problem`; `qr_manifest.END_TIME` where the solver card's `time_end` is not the store's end). The settings cell is composed as the GUI's Run and notebook compose it: the solver card's defaults under the session's values. A solver card run twice in the card worker rewrites its store (`test_engine_rerun_rewrites_its_store`).
- **Pyodide** (`-m qr`): the same cells in Pyodide 0.29.3 under node, booted like `pyodide-worker.js` (a synchronous `XMLHttpRequest` is shimmed for `zoomy_core.misc.download`); plus the C1 bump on `SymbolicHyperbolicSolverNumpy` (t = 0.5, mass to 1e-12) and an import of every `zoomy_core` module.
- **Not in the browser:** Malpasset (jax) and Malpasset (AMReX) are submitted to a backend by the GUI; their Pyodide tests skip. The AMReX session (`time_end` 2000 s cut to 2 s) solves where AMReX builds: inside its image (`AMREX_HOME`) or through apptainer and `zoomy_amrex.sif`; elsewhere (CI) its CPython test runs the model and mesh cells only.
- **Live** (`render-webpage.yml`, after each deploy): `-m qr_live`, every target answers 200 and every project zip is served with the repo's file list; `-m qr_deploy`, the GUI serves this commit's wheels and the mirrored session data (`gui/gui/data/`).
- **Browser** (`-m qr_browser`, `test_qr_browser.py`): headless Chromium (Playwright) opens every QR URL that loads a session in the notebook view (`view=notebook` added where the code lacks it: "Open in Notebook Mode"), drives the GUI's notebook through the DOM (toolbar Run All, Clear All Outputs, + Code), appends one final cell, and runs all cells twice: the second Run All is the re-run that failed on the deployed site (the open store stopped the solver rewriting its file). The final cell (`session_runner.notebook_check_code`, one line) runs `notebook_check` in the kernel: every cell succeeded (`sys.zoomy_cell_log`, the kernel's record of each cell's outcome; also each cell's DOM status), and a solving session published a finite store with >= 2 snapshots up to its `time_end`. Malpasset (jax, AMReX) needs a backend: its model, mesh and settings cells must pass, run and visualization are not judged. GUI under test: `QR_GUI_BASE` (site root; `https://zoomylab.github.io/Zoomy` = deployed), else a local build served under `/Zoomy/`: `QR_GUI_SITE` (built by `docs/scripts/build_gui_site.sh SITE`, the deploy's own recipe), else built from the checkout. CI: `qr-cases.yml` (local build), `render-webpage.yml` after the deploy (live). Per test: screenshot, console log and `report.json` in its tmp dir.
- **Run:** `pip install -r tests/qr_cases/requirements.txt; npm ci --prefix tests/qr_cases/pyodide; pytest tests/qr_cases -m qr -n 4` (`-m qr_live` for the site); `pip install playwright; playwright install chromium; pytest tests/qr_cases -m qr_browser -n 3`.
- **Env:** `QR_MANIFEST` (manifest path), `QR_WHEELS`, `QR_PYODIDE_DIR` / `QR_NODE` (npm pyodide elsewhere), `QR_PYODIDE_CACHE`, `QR_STRICT=1` (CI: missing tools fail), `QR_GUI_BASE` / `QR_GUI_SITE`, `QR_BROWSER_TIMEOUT` (s per Run All, 900).
