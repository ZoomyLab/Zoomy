# 0003 — Align agent definitions with the steward model

**What:** Update the standalone agent definitions so they no longer reference
the deleted "hub" orchestration or git worktrees, which the project replaced
with the per-folder **steward** model.

**Where:**
- `~/.claude/agents/zoomy.md`
- `~/.claude/agents/zoomy-cases.md`
- (cross-check) `STEWARD.md` §8 already points to
  `~/.claude/agents/zoomy.md` for the "root-cause-not-workaround checklist", so
  that file must stay accurate.

**How (if clear):** Replace hub/worktree language with the steward rules from
`STEWARD.md`:
- One session owns exactly one folder (`/steward <path>`); coordination via
  `ORGANIZATION.md` requests; commit = done-signal.
- **Never** create a branch or worktree; commit on the default branch (`main`
  for submodules, `develop` for the superrepo root).
- **Never** add a `Co-Authored-By` / "generated by" trailer — project-wide rule.
- Keep the architectural pointer to `docs/book/authoring/{model,system-model,
  numerics}.md` (these were just rewritten and are current).

**Why:** Stale agent defs reintroduce abandoned workflows (hub coordination,
worktrees) that contradict the steward protocol and the no-branch rule, so a
fresh `zoomy` agent would act against current conventions.

**Learned:**
- The hub was removed in favour of `ORGANIZATION.md` + `STEWARD.md` (see the
  "Steward orchestration (replaces hub)" decision).
- These live under `~/.claude/agents/`, **outside** any git repo, so a steward
  cannot commit them — this task is an edit-in-place, flagged to the user.
